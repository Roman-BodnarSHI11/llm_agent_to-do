# Лабораторна робота №9 — Agents (LLM проєкт)

**Тема:** LLM-агент «Менеджер справ» (To-Do асистент).

## Задача

Користувач пише в чат звичайною мовою, наприклад: *«додай купити молоко на завтра і подзвонити мамі
в п'ятницю»*, *«що в мене в списку?»*, *«я вже купив молоко»*. Агент сам вирішує, які інструменти
викликати, у якому порядку і з якими аргументами. Потім він відповідає користувачу за результатами їх
виконання. Справи зберігаються у файлі `tasks.json`, тож не зникають після перезапуску.

- **Мовна модель:** вільна модель `gemma4:e4b`, запущена локально через [Ollama](https://ollama.com/)
(вона підтримує tool calling).
- **Інтерфейс:** [Streamlit](https://streamlit.io/): чат, налаштування моделі й таблиця поточних
справ у боковій панелі.

## Інструменти агента

Інструменти — це звичайні Python-функції. Бібліотека `ollama` сама будує з них JSON-схему
за type hints і docstring, тому вручну описувати схеми не потрібно.

| Інструмент | Що робить |
|---|---|
| `add_task(title, due)` | додає справу (дедлайн у форматі `YYYY-MM-DD` або порожній) |
| `list_tasks(include_done)` | повертає список справ у JSON (за потреби разом із виконаними) |
| `complete_task(task_id)` | позначає справу як виконану |
| `delete_task(task_id)` | видаляє справу |

## Як працює агент

Функція `run_agent()` в `app.py` реалізує класичний цикл агента:

1. Модель отримує історію чату та список інструментів.
2. Якщо модель просить викликати інструменти, агент виконує їх і додає результати в історію

   (`role: "tool"`), а потім знову викликає модель.
3. Цикл закінчується, коли модель дає звичайну текстову відповідь (або після 10 кроків).

Якщо інструмент кидає помилку (неіснуючий `id`, неправильна дата), агент передає її текст моделі.
Так модель може виправитися: наприклад, спершу викликати `list_tasks`, щоб знайти правильний `id`.
У системному промпті є календар на найближчий тиждень. Без нього невелика модель вгадувала рік
і помилялася з днями тижня у запитах на кшталт «у п'ятницю».

У чаті видно кожен виклик інструмента з аргументами (🔧) і його результат (↳).

## Структура

```
lab_9/
├── app.py            # інструменти, цикл агента та інтерфейс Streamlit
├── requirements.txt
├── README.md
└── tasks.json        # створюється автоматично, «база даних» справ
```

## Запуск

```bash
ollama serve                 # якщо сервер ще не запущений
ollama pull gemma4:e4b       # модель з підтримкою tools
pip install -r requirements.txt
streamlit run app.py
```

Застосунок відкриється за адресою http://localhost:8501. У боковій панелі можна змінити адресу
Ollama-сервера та модель (підійде будь-яка модель з міткою `tools`, наприклад `qwen3.5:4b`).
Модель локальна, тому API-ключ не потрібен.

## Приклад діалогу

```
👤 Додай купити молоко на завтра і подзвонити мамі в п'ятницю
🔧 add_task(due='2026-11-12', title='купити молоко')
🔧 add_task(due='2026-11-13', title='подзвонити мамі')
🤖 Я додав два завдання: «купити молоко» на 2026-11-12 та «подзвонити мамі» на 2026-11-13.

👤 Я вже купив молоко
🔧 complete_task(task_id=1)
🤖 Задача «Купити молоко» відмічена як виконана.
```
